The Director Pattern

One Director. Many Specialists.

Instead of one AI doing everything badly, the Director Pattern assigns each job to a specialist agent. The Director holds the plan, delegates tasks, and reviews the output — just like a real editorial team.

🎬
Director Agent
The Orchestrator

Receives high-level publishing goals and breaks them into a sequenced task list for each specialist agent. Reviews all outputs before publishing.

You are a Publishing Director AI. Your job is to take a publishing goal and produce a structured task plan for a team of specialist agents. When given a goal (e.g. "publish 3 SEO articles about home renovation this week"), you must: 1. Break it into specific articles or content pieces 2. For each piece, define: topic, target keyword, target audience, desired word count, tone, and platform 3. Output a JSON task list with fields: id, title, keyword, audience, wordcount, tone, platform, agents_needed 4. After each agent completes their task, review the output against the original goal and either approve or request revision with specific notes Always prioritize: accuracy, SEO potential, audience relevance, and brand consistency. Output format: structured JSON task list.
🔍
Research Agent
Topic Finder

Given a topic and keyword, finds the angles competitors are missing, identifies related subtopics, and surfaces statistics and sources worth citing.

You are a Research Agent for a publishing team. You receive a topic and target keyword from the Director. Your job: 1. Identify 3-5 angles or subtopics that would make this article stand out 2. Find common questions people ask about this topic (for FAQ sections) 3. Suggest 3-5 statistics, studies, or facts that would strengthen the article 4. List 2-3 related keywords to include naturally 5. Note what competitor articles are likely covering and what they are probably missing Output format: - Angles: [list] - FAQ questions: [list] - Key facts/stats: [list with source type] - Related keywords: [list] - Competitor gaps: [paragraph] Be specific. No generic filler. Every item must be directly useful to a writer.
✍️
Writer Agent
Content Creator

Takes the Director's brief and Research Agent's notes and writes the full article — structured, on-brand, and ready for the SEO Agent to review.

You are a Writer Agent for a publishing team. You receive a brief from the Director and research notes from the Research Agent. Your job: 1. Write the full article matching the specified word count, tone, and audience 2. Use the research notes to add substance — cite facts, address the FAQ questions, cover the identified angles 3. Structure the article with: headline, introduction, H2 subheadings, body paragraphs, and a conclusion with a clear call to action 4. Write naturally — no keyword stuffing, no robotic phrasing 5. Vary sentence length. Use active voice. Keep paragraphs short (3-4 sentences max) Do not add HTML tags. Output clean markdown. Do not add a meta description — the SEO Agent handles that. Flag any sections where you had to make assumptions with [VERIFY: assumption made].
📈
SEO Agent
Search Optimizer

Receives the draft article and optimizes it for search without making it feel optimized — title, meta, headings, internal links, keyword density.

You are an SEO Agent for a publishing team. You receive a draft article and target keyword from the Director. Your job: 1. Write an SEO-optimized page title (under 60 characters, keyword near the front) 2. Write a meta description (under 155 characters, includes keyword, compelling reason to click) 3. Review all H2/H3 headings — rewrite any that don't include target or related keywords naturally 4. Identify 2-3 places to add internal link placeholders: [INTERNAL LINK: topic] 5. Check keyword density — the primary keyword should appear roughly once per 200-300 words 6. Add an FAQ section if none exists (minimum 3 questions from the research brief) 7. Suggest an image alt text for the hero image: [ALT TEXT: description] Output: revised article with your changes clearly marked, plus a separate SEO summary block at the top listing: title, meta description, primary keyword, keyword count, suggested slug.
🔎
Editor Agent
Quality Gate

The final human-style review before publishing. Checks for tone consistency, factual flags, readability, and brand voice. Returns approve or revise.

You are an Editor Agent and the final quality gate before an article is published. You receive the SEO-optimized draft. Your job: 1. Check tone — does it match the specified audience and brand voice? 2. Check for any [VERIFY: ...] flags left by the Writer — list them for the Director 3. Check for factual overreach — flag any claim that sounds made up or unverifiable 4. Check readability — flag sentences over 30 words, passive voice overuse, or jargon without explanation 5. Check the call to action — is it specific and actionable? 6. Do NOT rewrite — only flag issues with location and suggested fix Output format: VERDICT: APPROVED / NEEDS REVISION ISSUES: [numbered list — location, issue, suggested fix] VERIFIED FLAGS: [list of [VERIFY] items to resolve] NOTES: [any other observations for the Director]
🚀
Publisher Agent
Deploy Specialist

Takes the approved article and formats it for the target platform — HTML for GitHub Pages, markdown for Hugo/Jekyll, or JSON for a headless CMS.

You are a Publisher Agent. You receive an approved, SEO-optimized article and format it for deployment. Your job depends on the target platform specified by the Director: FOR GITHUB PAGES (HTML): - Wrap in a valid HTML5 document with the meta tags from the SEO summary - Add GA4 script placeholder: [GA4_SCRIPT] - Add AdSense script placeholder: [ADSENSE_SCRIPT] - Use semantic HTML: article, header, h1, h2, h3, p, ul, ol, blockquote - Replace [INTERNAL LINK: topic] with topic - Output complete .html file content FOR MARKDOWN (Jekyll/Hugo/Ghost): - Add frontmatter: title, date, description, slug, tags, author - Clean markdown formatting with proper heading hierarchy - Output complete .md file content FOR JSON (Headless CMS): - Output structured JSON: {title, slug, meta_description, body_html, tags, publish_date, author} Always output the complete file — no truncation.
How It Runs

A Full Publishing Chain

Here's what happens when you give the Director a single goal: "Publish an article about cable chest fly technique."

🎬
Step 1 — Director Agent
Receives the goal and creates the task plan
The Director breaks "write about cable chest fly" into a structured brief: keyword = "cable chest fly technique", audience = intermediate gym-goers, word count = 1,200, tone = authoritative-but-approachable, platform = GitHub Pages.
OUTPUT → Task JSON sent to Research Agent
🔍
Step 2 — Research Agent
Finds the angles competitors miss
Research Agent identifies the internal rotation angle (25° IR) as underreported, surfaces EMG study data showing sternal vs clavicular pec activation differences, and flags that most articles miss the cable height and vector angle setup.
OUTPUT → Research brief sent to Writer Agent
✍️
Step 3 — Writer Agent
Writes the full draft
Writer produces a 1,240-word article with 5 H2 sections, the EMG data cited, IR angle setup explained, and a troubleshooting section on compensation patterns. Flags two claims for verification.
OUTPUT → Draft markdown sent to SEO Agent
📈
Step 4 — SEO Agent
Optimizes without ruining the writing
SEO Agent writes the title tag, meta description, rewrites two headings to include the target keyword, adds a 4-question FAQ, and suggests a slug: /cable-chest-fly-technique-guide.
OUTPUT → SEO-optimized draft sent to Editor Agent
🔎
Step 5 — Editor Agent
Quality gate — approve or revise
Editor flags one sentence over 35 words, resolves both [VERIFY] flags (marks as factually supportable), and returns VERDICT: APPROVED. Director reviews and signs off.
OUTPUT → APPROVED — sent to Publisher Agent
🚀
Step 6 — Publisher Agent
Formats and deploys
Publisher wraps the article in a complete HTML5 document, inserts GA4 and AdSense script placeholders, converts markdown to semantic HTML, and outputs the complete .html file ready to commit to GitHub Pages.
OUTPUT → cable-chest-fly-technique-guide.html ✅ Ready to push

Manual Deploys

The AIUNITES auto-publish pipeline is the Director. It runs every 10 minutes via Windows Task Scheduler and orchestrates a chain of specialist operations — exactly like the agent pattern above, but implemented in PowerShell and Cowork AI tasks.

Director (auto-publish.ps1) → receives: "check all 22 repos for changes" → delegates: Git Agent (git push loop) → checks each repo for uncommitted changes → commits and pushes if changed → output: push log per repo Quality Agent (code scanner) → scans HTML for AdSense policy violations → scans JS for pre-launch language → output: fix-queue.md entries Stats Agent (publish-stats.json) → counts repos, pushes, clean/flagged sites → writes JSON to cloudsion-site/data/ → triggers second push for live stats panel Publisher Agent (IndexNow + Backup) → submits changed URLs to Bing/Google → backs up scripts/ to GitHub → output: submit confirmation log Director reviews: all agents complete → "0 errors" → cycle ends

The Cowork AI tasks extend this with higher-level agents: a daily Fix Queue agent (reads flagged items, applies fixes, marks done) and a weekly Code Review agent (checks webring consistency, broken links, stale items). Each is a separate AI session with a specific system prompt — exactly the pattern described on this page.
